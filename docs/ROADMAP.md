# Growth Learning 路线图

路线图按可验证的产品闭环推进。每阶段都要求迁移、测试、权限检查、可观测性和文档同步，不以页面数量衡量完成度。

## Phase 1：工程基础（当前）

目标：形成专业、干净、可运行、可测试、可长期演进的单体工程基础。

- 产品、架构、数据和 API 文档
- FastAPI 配置、健康检查、数据库迁移、Redis/MinIO/AI 接口基础
- Next.js App Shell、首页、开发状态页和 API client
- PostgreSQL、Redis、MinIO、前后端 Docker Compose
- Windows/Linux 开发脚本、CI 和完整启动说明

退出条件：本地检查通过；Compose 配置可复现；新电脑按 README 能启动；Git 历史为逻辑提交。

## Phase 2：家庭、身份与权限

目标：让一个家庭安全地创建儿童档案并管理协作者。

- User、Family、FamilyMember、Child 的首批正式迁移
- 身份会话与家庭上下文
- 家长/陪伴者权限矩阵和服务层授权
- Teacher 与 TeacherChildRelation 的有限、到期、可撤销授权
- 审计事件和基础家庭设置 UI

退出条件：跨家庭访问测试、老师授权生命周期测试和管理员保护规则全部通过。

## Phase 3：知识模型与汉字学习闭环

目标：用通用知识点模型交付第一个完整的汉字学习流程。

- Subject、Ability、KnowledgePoint、KnowledgeRelation
- 课程、单元、学习活动的版本化发布
- LearningRecord 追加式写入与幂等接口
- ChildKnowledgeState v1 计算器、版本与证据解释
- 儿童学习界面和家长可解释进度视图

退出条件：完成“活动 → 原始记录 → 状态计算 → 家长解释”的端到端闭环，并能从事实表重建状态。

## Phase 4：测评与自适应复习

目标：建立可靠的评估、识字量估算和低负担复习循环。

- AssessmentSession/Item 与题目快照
- 基线/阶段测评和带置信区间的识字量估算
- ReviewSchedule/Record 与算法版本化
- 每日负担、到期优先级、暂停和家长控制
- 算法离线回放、重算和新旧版本对比工具

退出条件：历史事件保持不变，算法升级可重算；计划解释清晰且遵守家庭负担设置。

## Phase 5：受控 AI 阅读

目标：基于孩子真实掌握范围生成可安全验证的阅读体验。

- AI provider 适配器与供应商切换配置
- 提示模板、模型调用审计和成本/速率控制
- 已掌握字符约束、超纲扫描和内容安全规则
- Story 版本与 ReadingSession、理解题记录
- 家长预览/控制和失败降级内容

退出条件：供应商可替换；未通过规则的内容不会展示；常规测试不依赖真实 AI。

## Phase 6：科学实验与成长记录

目标：把家庭线下探索和长期成长证据纳入同一平台。

- 版本化实验课程、风险等级和家长准备卡
- 实验会话、观察、结论与媒体上传
- GrowthEvent 时间线与里程碑
- 周期报告、证据引用和家长批注
- 家庭数据/媒体导出与恢复演练

退出条件：安全规则强制执行；媒体归属和生命周期明确；家庭可获取可读、版本化的完整导出。

## Phase 7：质量、规模与持续优化

目标：在真实使用证据基础上提升可靠性和个性化质量。

- 可访问性、性能预算、备份恢复与安全审计
- 任务队列、可观测性和依赖就绪探针
- 掌握/复习算法评估指标与受控实验
- 多设备同步、离线容错和数据冲突策略
- 基于真实边界评估模块拆分，默认继续保持模块化单体

## 近期优先级（Phase 1 之后）

1. 先确定家庭/儿童/老师授权的数据契约和权限测试矩阵。
2. 再以少量真实汉字内容验证通用 KnowledgePoint 与活动版本模型。
3. 最后实现原始学习记录到可重算掌握状态的最小端到端切片。
