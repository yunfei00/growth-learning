# Growth Learning 产品需求文档

## 1. 产品愿景

Growth Learning 是一个面向儿童长期学习与成长记录的家庭中心平台。产品不以短期刷题或单次分数为目标，而是持续保存可解释、可迁移的原始学习证据，帮助孩子、家长和经授权的老师形成稳定的学习闭环。

V1 从汉字识字切入，逐步覆盖自适应复习、识字量评估、受控 AI 阅读、周末科学实验、成长时间线与长期报告。

## 2. 产品原则

1. **儿童利益优先**：减少排名和成瘾性机制，不使用暗黑模式，重要建议由家长确认。
2. **家庭拥有数据**：家庭管理员控制成员、授权、导出和删除；老师只访问明确授权的孩子和数据范围。
3. **证据与结论分离**：学习、测评、复习的原始记录长期保存；掌握状态是可重算的派生结果。
4. **通用能力模型**：`KnowledgePoint` 不绑定汉字业务，汉字是首个完整领域而不是系统边界。
5. **AI 受规则约束**：AI 负责生成和建议，确定性规则负责权限、学习范围、复习计划和内容安全边界。
6. **长期可用**：数据模型、导出格式和审计信息应支持 5–10 年以上的连续记录。

## 3. 用户与角色

| 角色 | 核心诉求 | 默认权限 |
| --- | --- | --- |
| Parent（家长） | 配置学习计划、查看成长趋势、准备实验材料、管理授权 | 管理所属家庭及孩子；确认 AI/老师建议 |
| Child（孩子） | 完成短时学习、复习、阅读和实验活动 | 访问分配给自己的活动与反馈 |
| Teacher（老师） | 了解被授权孩子的学习情况并给出建议 | 仅访问家长授权的孩子、字段和有效期 |
| Companion（陪伴者） | 协助完成日常学习或实验 | 仅执行家长授予的有限操作，不管理敏感设置 |
| System（系统） | 计算掌握状态、安排复习、生成可解释建议 | 不能绕过家庭权限或内容安全规则 |

一个用户可加入多个家庭并在不同家庭拥有不同角色。儿童档案属于家庭，不等同于可登录的用户账号。

## 4. V1 核心场景

### 4.1 家庭与授权

- 家长创建家庭、儿童档案并邀请其他家长或陪伴者。
- 家长向老师发放有范围、有期限、可随时撤销的授权。
- 高风险操作（成员管理、完整导出、删除、扩大老师权限）需要家庭管理员权限并保留审计信息。

### 4.2 汉字学习与掌握度

- 以通用知识点表达汉字、词语、能力和先修关系。
- 每次学习都写入不可变的 `LearningRecord`；测试与复习分别写入对应原始记录。
- 系统根据原始记录和算法版本计算 `ChildKnowledgeState`，展示掌握度、置信度、证据数量和下次复习时间。
- 算法升级时可按历史事件重算，不覆盖原始证据。

### 4.3 动态复习与测评

- 复习计划综合遗忘风险、掌握置信度、最近错误、知识点依赖和每日负担。
- 测评支持基线测试、阶段测试和识字量估算；结果包含置信区间，不把一次测试当作永久能力结论。
- 家长可以调整学习强度、暂停建议或手动安排内容。

### 4.4 AI 故事阅读与理解

- 故事生成输入包含年龄段、兴趣、目标长度和“已掌握/允许出现”的汉字集合。
- 生成后由确定性校验器检查超纲字符、内容安全、长度和结构；不合格内容不得直接展示给孩子。
- 阅读会话记录实际阅读版本、理解题作答和反馈，保留生成模型与提示模板版本用于追溯。

### 4.5 周末科学实验

- 提供按年龄、时长、材料、风险等级组织的实验课程。
- 家长准备卡明确材料、步骤、安全提示和成人参与要求。
- 孩子可记录观察、照片和结论，形成成长事件；AI 建议不能替代安全规则。

### 4.6 家长驾驶舱与成长档案

- 首页优先展示今天需要关注的事项、学习节奏和可解释趋势，不使用虚假排行榜。
- 时间线聚合学习里程碑、作品、实验和家长记录。
- 周期报告汇总证据、趋势和建议，并可导出开放格式以便长期保存。

## 5. 功能范围

### V1 必须具备

- Family、成员角色和儿童档案
- 老师有限授权模型
- Subject、Ability、KnowledgePoint 与关系图
- 汉字学习活动、原始学习记录和派生掌握状态
- 测评、识字量估算、动态复习
- 受已掌握汉字约束的 AI 故事与阅读理解
- 科学实验课程、准备卡和实验记录
- 成长时间线、报告、媒体与数据导出
- 家长对 AI 建议、分享和授权的控制

### Phase 1 只交付工程基础

- 产品与技术文档
- Next.js 应用壳、首页、开发状态页和 API 客户端
- FastAPI 健康检查、版本路由、配置与基础集成接口
- PostgreSQL、Redis、MinIO 的可复现本地环境
- 自动化测试、静态检查、构建和 CI

### V1 暂不包含

- 完整商业化、学校级多租户或公开社交功能
- 用 AI 自主决定权限、评分或高风险安全结论
- 微服务、Kubernetes 或与阶段目标无关的复杂基础设施

## 6. 关键业务规则

- 原始事件采用追加式写入；纠错通过状态或补偿记录表达，禁止用当前分数替代历史。
- 所有家庭域数据都必须携带家庭归属，并在服务层执行授权校验。
- `ChildKnowledgeState` 必须包含算法版本和最后计算时间，可从原始记录重建。
- 老师授权至少包含孩子、数据范围、允许动作、生效时间、过期时间和撤销状态。
- 媒体使用对象存储，数据库仅保存对象键、所有者、用途、哈希和元数据。
- AI 生成内容必须记录供应商、模型、模板版本、规则校验结果和人工确认状态。

## 7. 非功能需求

- **隐私与安全**：最小权限、密钥只从环境读取、传输加密、敏感操作审计、儿童数据默认不公开。
- **可解释性**：掌握状态和建议可以追溯到证据类型、时间范围与算法版本。
- **可靠性**：关键写入具备幂等键；异步任务可重试且不重复产生业务事件。
- **可移植性**：支持按家庭导出结构化数据和媒体清单；导出格式带版本。
- **可访问性**：核心界面支持键盘操作、清晰焦点和足够对比度；儿童界面保持低认知负担。
- **可观测性**：请求 ID、结构化日志、健康检查和基础指标从工程起步阶段保留扩展点。
- **性能目标**：常规 API 在正常负载下 P95 小于 500 ms（不含外部 AI 调用）；页面核心内容优先服务端渲染。

## 8. 成功指标

- 每周有学习记录的儿童比例与连续活跃周数
- 到期复习完成率及单日负担是否处于家长设定范围
- 掌握状态中具有足够证据和置信度的知识点比例
- 阅读故事的超纲字符率、校验拦截率与理解完成率
- 实验活动完成率及家庭主动记录的成长事件数量
- 家长查看并采纳/忽略建议的比例（不以无条件采纳为目标）
- 数据导出成功率、授权撤销生效时间与审计完整率

## 9. 待产品验证问题

- 不同年龄段的单次学习时长与家长可接受提醒频率
- “认识、理解、书写、应用”是否应作为独立能力维度呈现
- 老师最小可用的数据范围与家长最容易理解的授权语言
- AI 故事中生字比例的默认阈值和按上下文容忍策略
- 识字量估算结果的呈现方式，如何避免给孩子造成标签化压力
